# Beautique Bar — SEO & tracking foundation (MARKETING-SETUP.md)

Read this first if you are a person or an AI agent asked to "connect GA4, GTM, Search Console and Google Ads".
**The website does not need restructuring for any of that.** Everything below is already in place; the remaining work
happens inside Google's tools. Last full pre-launch audit: 28 Sep 2026.

---

## 1. How the site is built

| Thing | Where |
|---|---|
| Generator (all inner pages) | `opus-site-src/build.py` → writes `opus-design-v1/` (preview, hidden from search) |
| Launch copy | `opus-site-src/make_production.py` → writes `opus-site-production/` (what goes on beautiquebar.com) |
| Tag-test copy | `make_production.py --tagtest` → `opus-site-tagtest/` (production + GTM, but noindex) |
| **Single source of truth** | `opus-site-src/site_config.py`: domain, GTM ID, verification codes, salon names/addresses/phones/emails/hours/booking links/socials |
| Homepage | `opus-design-v1/index.html` is hand-authored; `build.py` refreshes its header/footer/head and **fails the build** if its phone, Fresha, map links or hours differ from `site_config.py` |
| Conversion events | `opus-design-v1/site.js`, block "Conversion events" |
| Redirects | `opus-design-v1/_redirects` (copied into both builds) |
| Security headers / pages.dev noindex | generated by `make_production.py` into `_headers` |

Build order: `python3 opus-site-src/build.py && python3 opus-site-src/make_production.py` (add `--tagtest` for the test copy).
Hosting: Cloudflare Pages (direct upload with wrangler). Static HTML — every URL is a real page, no client-side routing,
so crawlers and GA4 page views need nothing special.

## 2. Domain, canonical & indexing

- Production domain: **https://beautiquebar.com** (no www, HTTPS, trailing slash on every page). Set in `site_config.py` → `SITE_URL`
  (override for a one-off build with env `BB_SITE_URL`). It drives canonical tags, `og:url`, schema URLs, RSS, robots.txt and the sitemap.
- Every page has `<link rel="canonical">` to its own https://beautiquebar.com/…/ URL.
- **Preview/staging never indexes:** the preview and tag-test builds carry `noindex,nofollow` on every page, and the tag-test build also
  sends `X-Robots-Tag: noindex` and `Disallow: /`. The production build's `_headers` adds `X-Robots-Tag: noindex` for any
  `*.pages.dev` host, so the Cloudflare project URL can never compete with the real domain.
- Production `noindex,follow` only on: `/thank-you/` (no form on this site), `/skin/body-piercing/` (service discontinued, URL kept for old links), `404.html`.
- **www → non-www** is not something the site files can do: add a Cloudflare Redirect Rule `www.beautiquebar.com/*` → `https://beautiquebar.com/$1` (301) when the domain is attached.
- `/x` → `/x/` is handled automatically by Cloudflare Pages (one hop).

## 3. Sitemap & robots

- Sitemap: **https://beautiquebar.com/sitemap.xml** — generated on every production build from the pages that exist (new pages are included automatically; noindex pages are excluded).
  `lastmod` only changes when a page's main content changes (hashes kept in `opus-site-src/sitemap-lastmod.json` — commit it).
- robots.txt: `Allow: /` + `Sitemap:` line (production); `Disallow: /` on the tag-test build.
- Submit the same sitemap URL in Google Search Console and Bing Webmaster Tools.

## 5. Metadata system

- Titles/descriptions for the main pages: `SEO` dict in `build.py` (one line per page). Blog posts: front-matter; the " | Beautique Bar" suffix is added only when the title stays under ~65 characters (or set `seoTitle`).
- Open Graph + Twitter card tags come from `head_common()` for every page (shared image `/img/og-default.jpg`, 1200×630).
- Icons: `favicon.ico` (BB monogram), `apple-touch-icon.png`, `icon-192/512.png`.

## 6. Structured data (JSON-LD, generated in `build.py`)

- Every page: `HealthAndBeautyBusiness` (the brand, `@id …/#organization`, logo, socials, links to both salons).
- Home: `WebSite` + both `NailSalon`s. Each location page: its `NailSalon` (address, phone, per-salon email, hours, map, Instagram,
  `ReserveAction` → its Fresha link, price catalogue taken from the menu — prices are the site's real prices, nothing invented).
- Service pages: `Service` (provider = both salons). Posts: `BlogPosting`. All inner pages: `BreadcrumbList` (built from the visible breadcrumb).
- No reviews/ratings/FAQ schema (none are shown on the site — don't add them unless real, visible content exists).
- All values come from `site_config.py`, so changing a phone/hours there updates the page text and the schema together.

## 7. Tracking architecture — ONE tag: Google Tag Manager

- **Only Google Tag Manager is installed** (container `GTM_ID` in `site_config.py`, currently `GTM-M6WHQ2D5`), production build only, on every page (head snippet + noscript).
- **GA4, Google Ads conversion tags, remarketing, and any future tags are added inside GTM — never as extra `gtag.js` snippets in the site.** A second GA4/Ads snippet would double-count page views and conversions.
- Page views: normal page loads (static site) — a GA4 Google Tag in GTM firing on *Initialization – All Pages* is all that's needed.
- No IDs for GA4 or Google Ads exist in the website code, by design. There is nothing to "add later" in the site for them.

### Conversion events (dataLayer) — already live on every page

`site.js` pushes exactly one event per click (verified on all 434 tracked links, 28 Sep 2026):

| Event | Fires when someone clicks | Useful as |
|---|---|---|
| `bb_book` | any Fresha booking link | **Primary Ads conversion** (booking click) |
| `bb_call` | any `tel:` link | **Ads conversion** (phone click) |
| `bb_text` | any `sms:` link | secondary conversion |
| `bb_directions` | any Google Maps link | secondary / GBP-style action |
| `bb_email` | any `mailto:` link | secondary |

Parameters on every event: `bb_salon` = `yonge` \| `bridlewood` (never unknown), `bb_link` = the href, `bb_placement` = where on the page
(`header`, `booking-dialog`, `mobile-menu`, `hero`, `salon-card`, `salon-details`, `prices`, `contact`, `closing`, `footer`, `article`, …).
Detection is by link type, so any new booking/phone/map link added anywhere is tracked automatically — no attributes to remember.

**GTM wiring (for the agent that connects accounts):**
1. Data Layer Variables: `bb_salon`, `bb_link`, `bb_placement`.
2. Custom Event triggers: `bb_book`, `bb_call`, `bb_text`, `bb_directions`, `bb_email` (or one regex trigger `^bb_`).
3. GA4 Event tag → event name `{{Event}}`, params salon/link/placement. Mark `bb_book` and `bb_call` as key events in GA4.
4. Google Ads Conversion tags on `bb_book` and `bb_call` (optionally split by `bb_salon` into Yonge / Bridlewood conversions) + Conversion Linker on All Pages + Ads Remarketing if wanted.
5. **Do not** also create "Click URL contains fresha / tel:" triggers — those would duplicate the `bb_*` events.
6. Test on the tag-test preview (https://tag-test.beautique-bar-opus-design-v1.pages.dev) with Tag Assistant before publishing the container.

### Fresha — what can and can't be measured from this site
- The site can measure the **booking click** (`bb_book`). The booking itself is completed on fresha.com, which this site cannot see.
- **Completed bookings** can only be tracked through Fresha's own marketing/tracking integration (in Fresha's settings — check what Fresha currently offers for Google Analytics / Google Ads), or via Reserve with Google. Nothing on the website needs to change for that.
- Booking links (in `site_config.py`): Yonge `…/beautique-bar-on-yonge-…-e0fzhnga/booking?menu=true`; Bridlewood `…/nails-for-you-beautique-bar-…-bkuolnwc/booking?menu=true&pId=32159`
  (changed 28 Sep 2026 from the old `/book-now/nails-for-you-m7weksrj/…` link, which redirected to a Book/Group/Gift chooser; both now open straight on the service menu). Both open in a new tab.

### Consent
No cookie banner today (see privacy policy draft). If one is added, configure Google Consent Mode v2 inside GTM — still no site restructuring.

## 8. Verification (Search Console / Bing)

- Best: Search Console **Domain property** via a DNS TXT record in Cloudflare — no website change.
- If you need the HTML-tag method: put the code in `site_config.py` → `GOOGLE_SITE_VERIFICATION` (or env `BB_GOOGLE_SITE_VERIFICATION`), rebuild production. Bing: `BING_SITE_VERIFICATION`, or simply import the site from Search Console.

## 9. Redirects (`opus-design-v1/_redirects`)

QR codes `/yonge`, `/warden` → location pages · `/home/` → `/` · 17 old WordPress post URLs → `/blog/<slug>/` · old WordPress pages
`/about/`, `/faqs/` → `/`, `/salons/` → `/locations/`, `/gallary/` → `/gallery/` · `/category/*`, `/tag/*`, `/author/*` → `/blog/` · `/feed/` → `/rss.xml` · `/shop/` → `/`.
All single-hop 301s. Every URL from the old WordPress export and the current Astro site is covered.

## 10. Performance notes

Self-hosted fonts with metric-matched fallbacks (no layout shift while fonts load). `build.py` generates smaller copies of photos
(`-800`, `-1200`, and `-xs` for gallery thumbnails) and adds `srcset` to every image automatically — phones download far less; desktops still get the originals.
Never edit the generated `-800/-1200/-xs` files; replace the original and rebuild.
